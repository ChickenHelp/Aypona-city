Bureau 102 · Kit des développeurs

Kit Aypona OS 2

Tout ce qu'il faut pour qu'une app parle au système : un fichier JavaScript, un protocole de messages, un manifeste. L'app tourne dans un cadre isolé ; elle ne voit que ce que le système lui donne.

1. Brancher le kit

Copiez aypona.js à côté de votre page, puis :

<script src="aypona.js"></script>
<script>
  const os = await Aypona.connecter();       // { systeme, version, langue, theme, app, permissions }
  await Aypona.notifier('Bonjour', 'Depuis mon app');
  await Aypona.fichiers.ecrire('note.txt', 'Contenu');
  await Aypona.stockage.ecrire('score', 12);
  Aypona.sur('langue', l => document.documentElement.lang = l);
</script>

Essayez l'app d'exemple depuis Aypona OS 2 : Réglages › Développeur › Essayer l'app d'exemple.

2. Protocole

Le kit envoie { aypona: 2, type: 'connexion' } à la fenêtre parente ; Aypona OS répond par un MessageChannel privé. Chaque requête porte un id ; la réponse revient avec re, ok et data ou error.

fichiers.lirenomfichiers
fichiers.ecrirenom, contenu, mime (5 Mo au plus)fichiers
fichiers.supprimernomfichiers
stockage.lire · .ecrire · .supprimercle, valeur (256 Ko par app)aucune
permission.etat · .demandernom—

Événements poussés par le système : { evenement: 'langue' | 'theme', valeur }. Limites : 40 requêtes par seconde, 6 Mo par message. Une app qui ne se connecte pas dans les 9 secondes se voit proposer l'ouverture dans un onglet.

Permissions : demandées au moment de l'usage (une fois, toujours, refuser) et seulement si elles figurent dans le manifeste. Erreurs : permission-absente:<nom>, permission-refusee:<nom>, introuvable, doublon, trop-gros, plein, debit, delai.

3. Manifeste v1 et domiciles

Chaque app du catalogue neuf est décrite par un manifeste, validé par l'App Store de la ville avant 12 h d'audit de la Sécurité. Trois domiciles : privé (adresse réglée sur l'appareil, jamais publiée), service (https), public (GitHub Pages en https, ou apps/<id>/….html publié avec le système).
